# CLAUDE.md — прокси к ДБО «Центр-инвест»

## Что это

Сервис-посредник между PWA (репозиторий `pwa-ci`) и интернет-банком «Центр-инвеста».
У ДБО **нет публичного API**, поэтому прокси заходит в веб-версию банка через
Playwright и снимает данные: где-то перехватом JSON-ответов, где-то разбором текста
страницы. Отсюда все ограничения ниже.

Развёрнут на Railway, проект `delightful-essence`:
https://delightful-essence-production-413c.up.railway.app

## Запуск

```bash
npm install
npm start                       # localhost:3001
node --check server.js          # проверка синтаксиса
```

Переменные окружения (шаблон в `.env.example`, `.env` не коммитить):

| Переменная | Назначение |
|---|---|
| `DBO_LOGIN`, `DBO_PASSWORD` | учётные данные ДБО. **Обязательны** |
| `PROXY_TOKEN` | токен доступа к самому прокси, PWA шлёт его в `Authorization: Bearer` |
| `ALLOWED_ORIGINS` | разрешённые источники запросов через запятую |
| `BANK_SOCKS` | необязательно: SOCKS с российским IP, если банк блокирует хостинг по гео |

Без `DBO_LOGIN`/`DBO_PASSWORD` сервис поднимается, но на все банковские маршруты
отвечает `503`, а `/health` показывает `dboConfigured: false`. Так сделано осознанно:
падение процесса уводило бы деплой в бесконечный перезапуск.

Задать креды на Railway, не светя их в истории команд:
`node set-dbo-credentials.mjs`

## Деплой

Railway **не** подхватывает пуш в GitHub автоматически. Деплой руками:

```bash
railway up --service delightful-essence --ci
```

## Маршруты

Чтение: `/health`, `/api/accounts`, `/api/payments`, `/api/payments/:id`,
`/api/contractors`, `/api/templates` (справочник «Корреспонденты»), `/api/tariffs`,
`/api/statement`, `/api/sections`, `/api/sections/:key`, `/api/recon/documents`.

Запись: `/api/login`, `/api/logout`, `/api/payments` (POST), `/api/transfer-own` (POST).

Отладочные: `/api/nav-debug`, `/api/payments-debug`, `/debug/*` — отдают куски DOM
и сырые ответы банка, то есть реальные данные. Все они закрыты токеном.

## Правила безопасности

- **Учётные данные только из окружения.** Раньше они стояли значениями по умолчанию
  в `server.js` и работали в публично доступном сервисе с открытым CORS — любой,
  зная адрес, получал счета и выписки. Пароль остаётся в истории коммита `9d78252`,
  считать его скомпрометированным.
- **Файлы с реальными банковскими данными не коммитить и не класть в образ.**
  `_*.xml`, `_*.json`, `_*.png`, `.session.json`, `.deviceid`, `_token.txt`,
  `recon-documents.json` закрыты в `.gitignore` и `.dockerignore`. Второе важно:
  `Dockerfile` делает `COPY . .`.
- **`sign: true` двигает реальные деньги.** В `submitPayment` и `transferOwn` это
  подпись и отправка платежа в банк. Тестировать только с `sign: false` (черновик).

## Как устроено чтение банка

- `browser.js` — общая сессия Playwright (`ensureLoggedIn`), из неё работают все
  функции чтения.
- `webpay.js` — отправка платежа через внутренний REST банка (`/api/v1/ui/.../doAction`),
  надёжнее, чем клики по форме.
- `parsePaymentLines` — разбор текста выписки. Отсюда берутся операции.
- `getSectionData` — универсальное чтение раздела ДБО: слушаем JSON банка, кликаем
  пункт меню, вытаскиваем пары «подпись — значение». Список разделов в `DBO_SECTIONS`.
- `reconDocuments` — разведка документного API, только чтение.

## Известные ограничения

- **У операций нет идентификатора документа.** Выписка отдаётся текстом, id там нет.
  Прокси собирает устойчивый ключ `дата|номер|сумма`, этого хватает для просмотра,
  но **не** для подписи и удаления документов ДБО. Чтобы это изменить, нужно найти
  запрос, которым банк отдаёт список документов с их id, и действия над ними —
  для этого есть `/api/recon/documents` и `recon-documents.mjs`.
- **Статусы и направление разбираются из текста.** Слова `ГО`, `ИСПОЛНЕН`, `ЧЕРНОВИК`,
  `НА ПОДПИСЬ`, `В ОБРАБОТКЕ`, `ОТКЛОНЕН` берутся со страницы. Направление операции
  определяется по знаку суммы, если он есть: эвристика по префиксу «От:» в новом
  интерфейсе срабатывает не всегда и раньше помечала поступления списаниями.
- **Разделы ДБО не проверены на живом банке целиком.** Подписи пунктов меню в
  `DBO_SECTIONS` могут не совпадать с фактическими — тогда раздел откроется пустым.
- **Вёрстка банка может измениться в любой момент** и сломать разбор. Это цена
  отсутствия API, а не дефект кода.

## Полезные скрипты

- `set-dbo-credentials.mjs` — задать логин и пароль в Railway (пароль вводится
  без эха, в историю команд не попадает).
- `recon-documents.mjs` — разведка документного API с локальной машины.
- `diag_*.js`, `cap_*.js` — разовые скрипты разведки, оставлены как справка.

## Правила работы

- Общение и комментарии в коде — на русском.
- Проверять правки: `node --check browser.js && node --check server.js`.
- Разбор выписки можно проверять без похода в банк — на сохранённом тексте страницы
  (`_ui.json`, поле `bodyText`).
